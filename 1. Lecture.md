Birthday problem: Algorithm to check if any of two students have same birth time

*Potential algorithms*

1.
- Maintain a record
- Interview students in some order
-- Check if birthday in record
--- Return a pair
-- Add a new student to record
- Return None

This algorithm is efficient when there are just 4 students
comparing the possibilities, but for 300 students, it would be hard to argue
correctness.

To argue out, we use induction.

*Proof that its correct: Induction*
How can we setup induction, what do we need for an inductive proof?
For inductive proof, we need a Best Case (hypothesis, or something the can be maintained), and an Inductive step

We want to proof that at the end of interviewing all students, that
the algorithm has returned a pair or None

*Inductive Hypothesis:* If first k students contain a match, algorithm returned
a match before interviewing student k+1

Base case: k = 0 : does the hypothesis hold? Yes
Assume Inductive Hypothesis is true for k = k' { if k' contains match -> already returned by induction else if k' + 1 contains match, alg k'+1 checks agains all strudent birthdays }

Proof that its efficient
For efficiency, we don't measure time, instead we count fundamental operations. The idea
would be we want a measure of how well an algorithm perfoms.

We use asymptotic analysis for that.
We expect performance to depend on size of our input. (we usually us n for size of input)

Efficiency means how fast and algorithm runs and how much memory it uses
